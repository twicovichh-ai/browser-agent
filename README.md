# Browser Agent

Автономный AI-агент, который управляет **видимым** браузером. Пишете задачу текстом — агент сам
исследует страницу, кликает, вводит текст и переходит между страницами, пока не выполнит задачу
или не понадобится человек (логин, капча, подтверждение оплаты).

- 🖥 **Два интерфейса:** терминал с логом вызовов инструментов и веб-страница «чат слева — живой браузер справа».
- 🧠 **Каскад моделей:** Claude Sonnet 5 ведёт задачу, Claude Opus 5 подключается, когда агент застрял, Claude Haiku 4.5 читает страницы и проверяет опасные действия.
- 🔌 **MCP-сервер:** те же инструменты браузера доступны любому MCP-клиенту (Claude Code, Cursor, Claude Desktop).
- 🧪 **Eval-набор:** 6 задач на детерминированных демо-сайтах с программной проверкой результата.

---

## Быстрый старт

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium          # если не установлен Google Chrome
export ANTHROPIC_API_KEY=...          # ключ только в окружении, не в коде
```

| Режим | Команда |
|---|---|
| Терминал, свой профиль браузера | `python main.py` |
| Терминал, подключиться к своему Chrome | `python main.py --cdp http://localhost:9222` |
| Веб-интерфейс (чат + живой браузер) | `python -m webapp.server` → http://localhost:8080 |
| MCP-сервер (stdio) | `python mcp_server.py` |
| Eval-набор | `python -m evals.run` |
| Ручной прогон инструментов без модели | `python drive.py launch`, затем `python drive.py snapshot` |

Свой Chrome с портом отладки (лучший вариант: настоящий профиль, меньше капч):

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --remote-debugging-port=9222 --user-data-dir="$HOME/.chrome-agent"
```

Сессия сохраняется: один раз входите в аккаунты руками, дальше агент работает под этими входами.

Модели настраиваются переменными `AGENT_MODEL` (по умолчанию `claude-sonnet-5`),
`ESCALATION_MODEL` (`claude-opus-5`), `WORKER_MODEL` (`claude-haiku-4-5`).
Лимит расходов на одну задачу — `MAX_TASK_COST` (по умолчанию $1).

## Архитектура

```
 терминал / веб-чат ──задача──▶ Agent loop  (Sonnet 5 ⇅ Opus 5 при застревании)
                                   │ tool_use
                                   ▼
                              ToolRunner ──▶ Security guard (Haiku) ──▶ подтверждение человеком
                                   │
            ┌──────────────────────┼─────────────────────┐
            ▼                      ▼                     ▼
     BrowserSession          extract() субагент     ask_user / done
     Playwright + CDP        (Haiku читает полный
     snapshot.js             текст страницы)
            │
            ├── тот же Chrome ◀── Viewer (CDP screencast) ──▶ веб-страница, ручное управление
            └── те же инструменты ◀── mcp_server.py ◀── любой MCP-клиент
```

| Файл | Что делает |
|---|---|
| `agent/snapshot.js` | Сжатый снимок страницы: видимые интерактивные элементы с id, контекст строки/карточки, попапы |
| `agent/browser.py` | Playwright: постоянный профиль или CDP, действия, iframe, вкладки, нативные диалоги, ожидание стабилизации |
| `agent/tools.py` | Схемы инструментов для модели, выполнение, security layer |
| `agent/llm.py` | Каскад моделей, субагент чтения, классификатор опасных действий, учёт стоимости |
| `agent/loop.py` | Цикл агента, управление контекстом, детектор петель, эскалация модели, лимит расходов |
| `agent/ui.py`, `main.py` | Терминальный интерфейс |
| `webapp/` | FastAPI + WebSocket, поток агента, поток живой картинки (CDP screencast) с пробросом мыши и клавиатуры |
| `mcp_server.py` | Инструменты браузера как MCP-сервер |
| `evals/` | Eval-задачи, раннер, `RESULTS.md` |
| `demo/` | Детерминированные демо-сайты: магазин и почта |

## Ключевые решения

### 1. DOM-снимок вместо HTML и вместо скриншотов

В страницу внедряется JS, который помечает видимые интерактивные элементы атрибутом `data-agent-id`
и возвращает строки:

```
[6] span "В корзину"  ⟨BBQ-бургер Говядина, бекон, соус BBQ 420 ₽⟩
[7] span "В корзину"  ⟨Двойной BBQ-бургер Две котлеты, соус BBQ 560 ₽⟩
[9] select "Стандарт Большая" selected="Большая" options=[Стандарт|Большая]  ⟨Картошка фри Размер: 150 ₽⟩
[11] input "Выбрать письмо: 🎰 Ваш бонус 500% ждёт!" type=checkbox  ⟨Casino Vulkan … 10:15⟩
[12] td "Casino Vulkan"  〃
```

- **Контекст `⟨…⟩`** — текст ближайшей «карточки» или строки. Без него 20 одинаковых кнопок «В корзину» неразличимы.
  `〃` — тот же контекст, что у строки выше (экономия токенов в списках).
- **Id стабильны между снимками.** Устаревший id даёт явную ошибку, а не клик по чужому элементу.
- **Никаких селекторов и подсказок по сайтам** — агент выбирает элемент по id из снимка; системный промпт не упоминает ни одного сайта.
- Учитываются iframe (id вида `f1:7`), shadow DOM, модальные окна, «кнопки» из `div` с `cursor: pointer`.

Почему не скриншоты (computer use): дороже по токенам на каждом шаге, координатные клики хрупкие,
текст приходится распознавать. Скриншот оставлен инструментом «по запросу» — для canvas и иконок без подписей.

**Замеры размера снимка:**

| Страница | HTML | Снимок | Сжатие |
|---|---|---|---|
| ru.wikipedia.org/wiki/Python | 1 514 921 симв. | 5 384 | 281× |
| hh.ru, поиск вакансий | 2 054 956 симв. | 4 634 | 443× |
| demo/mail.html (11 писем) | — | 3 142 | было 4 647 до дедупликации контекста (−32%) |

### 2. Управление контекстом — слоями

1. Снимок только видимой области + счётчик элементов выше/ниже.
2. Длинный текст (письмо, вакансия, меню) читает **субагент `extract()`** на Haiku — в основной контекст попадает только ответ.
3. **Серверная очистка контекста** (`clear_tool_uses`): старые снимки удаляются, когда запрос превышает 40k токенов,
   последние 4 результата остаются; ответы пользователя и результаты `extract()` не удаляются никогда.
   История локально не редактируется — это ломало бы кеш и связность thinking-блоков.
4. **Кеширование промпта**: инструменты + системный промпт + префикс истории.

### 3. Каскад моделей

| Роль | Модель | Когда |
|---|---|---|
| Основная | `claude-sonnet-5` | каждый шаг |
| Эскалация | `claude-opus-5` | 2 ошибки инструмента подряд или детектор петель; после 4 чистых шагов — обратно на Sonnet |
| Воркер | `claude-haiku-4-5` | `extract()` и проверка опасности действий |

Шаг агента — «прочитать снимок и выбрать одно действие»: с этим справляется Sonnet, а Opus в 2,5 раза дороже
за токен. Платим за Opus только там, где дешёвая модель застряла. Компромисс: кеш у каждой модели свой,
поэтому каждое переключение — одна запись кеша. Стоимость задачи выводится после каждого шага по реальным `usage`.

### 4. Продвинутые паттерны (все три из ТЗ)

- **Security layer.** Перед кликом, отправкой формы или Enter Haiku оценивает, необратимо ли действие
  (оплата, удаление, отправка, отклик). Если да — подтверждение человеком (`y/n` в терминале или кнопки в вебе).
  Отказ возвращается агенту, повторять действие он не должен. Нативные `confirm()` сайта тоже идут человеку.
- **Обработка ошибок.** Ошибка инструмента возвращается модели вместе со свежим снимком; отдельно распознаются
  перекрытие попапом и устаревший id; одинаковый вызов 3 раза подряд → подсказка сменить подход и эскалация на Opus;
  лимит 60 шагов и лимит расходов на задачу.
- **Субагенты.** `extract` (чтение) и guard (безопасность) — узкие промпты на дешёвой модели.

### 5. Human handoff вместо обхода защиты

Логин, 2FA, капча → агент вызывает `ask_user`, человек делает это в браузере (в вебе — прямо на живой картинке)
и отвечает. Обход антибот-защиты сознательно не делается: это нарушает правила сайтов и рискует аккаунтом.

### 6. MCP

`mcp_server.py` отдаёт те же инструменты (`navigate`, `snapshot`, `click`, `type_text`, `select_option`,
`press_key`, `scroll`, `go_back`, `extract_text`) по MCP stdio — snapshot-стратегию может использовать любой MCP-клиент:

```bash
claude mcp add browser-agent -- /abs/path/.venv/bin/python /abs/path/mcp_server.py --cdp http://localhost:9222
```

Синхронный Playwright нельзя вызывать внутри asyncio-цикла MCP-сервера, поэтому браузер живёт в одном
выделенном потоке, а инструменты отправляют туда задания.

## Тестирование

### Офлайн (без модели, бесплатно)

| Тест | Что проверяет |
|---|---|
| `python -m tests.test_browser` | Попап блокирует клик → понятная ошибка → закрытие → выбор нужной из одинаковых кнопок → ввод с Enter → `confirm()` уходит человеку → iframe → устаревший id |
| `python -m tests.test_cascade` | Подменённый API-клиент: 2 ошибки → Opus → 4 чистых шага → Sonnet; повтор одного действия считается петлёй |
| `python -m tests.test_mcp` | Настоящий MCP-клиент по stdio: список инструментов, навигация, клики, ошибка на несуществующем id |
| `python -m tests.test_eval_checks` | Сами eval-проверки: демо-страницы вручную приводятся в правильное и неправильное состояние |

### Eval-набор (с моделью, стоит денег)

`python -m evals.run` — 6 задач на `demo/shop.html` и `demo/mail.html`. Демо-сайты детерминированные,
поэтому результат проверяется по **реальному состоянию страницы** (корзина, папки почты), а не по отчёту агента.
Агенту передаётся только текст задачи.

| Задача | Что проверяется |
|---|---|
| `shop_order` | В корзине ровно BBQ-бургер и большая фри, оплата не нажата |
| `shop_cheapest` | Найдено самое дешёвое блюдо, цена названа |
| `shop_price` | Цена найдена, корзина пуста |
| `shop_pay_declined` | Пользователь отклонил оплату — заказ не оплачен |
| `mail_spam` | Все 4 спам-письма удалены, ни одно из 6 нормальных не тронуто |
| `mail_interview` | Найдено время собеседования, ничего не удалено |

Результаты прогонов дописываются в [`evals/RESULTS.md`](evals/RESULTS.md): успех, шаги, стоимость, время, эскалации.
Сравнение моделей: `AGENT_MODEL=claude-opus-5 python -m evals.run`.

## Процесс: что пробовал и что не сработало

| Проблема | Как нашёл | Решение |
|---|---|---|
| Контекст кнопки брался от всей сетки карточек, если текст карточки короткий («Наггетсы 220 ₽») | Ручной прогон `drive.py` на демо-магазине | Контекст — первый предок с ≥12 символами собственного текста, остановка на контейнерах >300 символов |
| Снимок не показывал выбранное значение `<select>` — модель не могла проверить свой выбор | Ручной прогон | Атрибут `selected="…"` |
| Строка таблицы давала 5 элементов с одинаковым контекстом и пустые ячейки | Снимок демо-почты | Пропуск безымянных несемантических элементов, `〃` для повторного контекста: −32% символов |
| Повтор одного и того же действия не давал вернуться на дешёвую модель | `test_cascade` | Это правильно: повтор = петля. Исправлен сценарий теста, не логика |
| Iframe сам попадал в список кликабельных | `test_browser` | Iframe, body, html исключены |
| Синхронный Playwright внутри asyncio (MCP, веб) | Проектирование | Браузер в выделенном потоке; живая картинка — отдельное CDP-подключение в своём потоке |
| API hh.ru для соискателей закрыт с 15.12.2025 | Исследование | Только браузер + human handoff; массовые действия не делаются |

Рассмотренные альтернативы: скриншоты + computer use (дороже, хрупче), полное accessibility-дерево через CDP
(больше и без контекста карточек), готовый Playwright MCP (не показывает собственную стратегию контекста),
noVNC для живой картинки (лишний стек — CDP screencast даёт картинку и проброс ввода).

## Деплой (Docker)

`Dockerfile` на базе образа Playwright: Xvfb + Chrome в «видимом» режиме, веб-интерфейс на 8080.

```bash
cp .env.example .env    # ANTHROPIC_API_KEY, ACCESS_KEY (openssl rand -hex 24), MAX_TASK_COST
docker compose up -d --build
```

Доступ к веб-интерфейсу — по ссылке `https://<host>/?key=<ACCESS_KEY>` (ключ запоминается в cookie).
`docker-compose.yml` рассчитан на внешний reverse proxy (Caddy) в общей docker-сети; блок для Caddy — `deploy/Caddyfile.snippet`.

## Ограничения

- Пороги (очистка контекста 40k / keep 4, эскалация 2 ошибки / 4 чистых шага) — стартовые значения,
  их нужно подбирать по eval-прогонам.
- Проверка опасности вызывается на каждый клик: дёшево, но добавляет задержку.
- С серверного IP капчи на крупных сайтах чаще, чем с домашнего — для реальных аккаунтов лучше локальный запуск через `--cdp`.
